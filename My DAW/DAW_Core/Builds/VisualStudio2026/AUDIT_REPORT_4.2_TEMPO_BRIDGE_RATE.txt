SUMMARY — ROOT CAUSE ANALYSIS FOR SLOW PLAYBACK AT 91 BPM
================================================================================

HYPOTHESIS TESTED: Source read position scaled by tempo factor (bpm/120)

RESULT: REFUTED

No hardcoded 120 found in position conversion math.
No tempo/BPM enters source position or read increment calculation.
No PPQ/tempo-derived factor in render increment.


ACTUAL MECHANISMS FOUND:

1. BRIDGE RATE MISMATCH (CRITICAL BUG):
   - Bridge initialized at unknown rate (logged as 44100)
   - Actual device rate is 48000
   - m_engineSampleRate = 44100 (stale)
   - All length conversions multiply by 44100 instead of 48000
   - Result: clips computed as 91.875% of true length
   - Clips appear to play slow (duration mismatch)

2. FILE RATE FALLBACK (POTENTIAL BUG):
   - If file sample rate detection fails, defaults to 44100
   - If file is 48000 but treated as 44100, length is 8.125% too short
   - Could manifest as slow playback if file rate detection unreliable

3. SAMPLE RATE DOMAIN CONVERSIONS (WORKING CORRECTLY):
   - import: seconds → samples via multiplying by bridge rate
   - record: samples → seconds via dividing by bridge rate
   - No tempo enters these conversions

4. STRETCH/PITCH FACTORS (WORKING CORRECTLY):
   - pitch ratio = pow(2, semitones / 12) — independent of tempo
   - stretchRatio applied independently — no tempo scaling
   - Mode 3 Vocal uses stretchRatio from UI, not computed from BPM


LEADING CAUSE OF SYMPTOM:
==========================
Bridge rate initialized at device start. If device is 48000 but bridge = 44100:

At 48000 Hz:
- 480 output samples = 0.01 seconds
- Using bridge rate 44100: expected source samples = 0.01 * 44100 = 441
- Actual device rate: expected source samples = 0.01 * 48000 = 480
- SHORTFALL: 480 - 441 = 39 samples missing
- Per-block error: −8.125%

Pitch effect:
- Source advancing slower than expected
- Sample rate mismatch causes pitch shift down
- At 48000→44100 mismatch: pitch down ≈ −181 cents (below reference)
- Faster/slower pitch change would compound as clip progresses


HYPOTHESIS FOR 91 BPM SYMPTOM:
==============================
At 91 BPM:
- Project plays at 91/120 = 0.7583 of standard tempo
- If bridge rate = 44100 but device = 48000:
  - Clip lengths are 91.875% of true length (8.125% short)
  - Playback position mismatch causes BOTH slow playback + pitch down
  - 91 BPM triggers condition; 120 BPM bypasses (or bridge is re-wired)

SECONDARY EVIDENCE:
- "[EngineSync] Bridge wired. sampleRate=44100" logged
- No re-wire logged when project tempo changes
- m_engineSampleRate never updated after initial assignment
